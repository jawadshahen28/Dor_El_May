# دور المي — تلفيت | بوابة المواطنين وإدارة المجلس

دعم التطبيق القابل للتثبيت PWA وخطوات Android وiPhone وسياسة عدم تخزين البيانات الخاصة والتحديثات موثقة في [PWA.md](PWA.md). يبقى التطبيق والواجهة الخلفية والحسابات نفسها؛ لا توجد إشعارات دفع أو بيانات خاصة متاحة دون إنترنت.

تطبيق React عربي باتجاه RTL بالتعاون مع مجلس قروي تلفيت. يتضمن تسجيل الدخول، إنشاء الحساب، جلسات دائمة في MongoDB وصفحة للزائر. تعرض صفحة المواطن ملخص الضخ والأدوار القادمة وآخر إعلان منشور، ويتوفر جدول المياه وقائمة إعلانات المجلس وتفاصيلها. يستطيع المواطن إرسال بلاغات خاصة ومتابعة بلاغاته السابقة، وعرض حسابه وتسجيل الخروج. تتوفر بوابة مستقلة وآمنة للمجلس مع لوحة إحصاءات وإدارة حقيقية للأدوار والضخ. إدارة البلاغات والإعلانات والمواطنين والإعدادات، والإشعارات الفعلية وتحرير الحساب ليست منفّذة بعد.

إدارة المياه متاحة في `/admin/schedule` لإنشاء المسودات ونشر الأدوار وتعديل المواعيد وإلغاء الأدوار المؤهلة، وفي `/admin/water` لبدء الضخ وإنهائه وتسجيل الأوقات الفعلية والمسؤول وسجل الأدوار. خطوات الاستخدام وعقد API في [COUNCIL_WATER_MANAGEMENT.md](COUNCIL_WATER_MANAGEMENT.md). تدقيق الإشعارات وخطة Web Push والأحداث الثلاثة في [NOTIFICATION_READINESS.md](NOTIFICATION_READINESS.md)؛ الإرسال الفعلي غير مفعّل ولا تلزم أسرار جديدة.

دليل إدارة المجلس والملفات وعقد API وخطوات إنشاء المسؤول الأول في [ADMIN_SYSTEM.md](ADMIN_SYSTEM.md). لإنشاء مسؤول، شغّل `npm run admin:create` في PowerShell محلي تفاعلي؛ كلمة المرور مخفية ولا يُنشأ أي حساب تلقائيًا. بعد `npm run dev` افتح [دخول المجلس](http://127.0.0.1:5173/admin/login)، ثم [لوحة المجلس](http://127.0.0.1:5173/admin). لا يوجد تسجيل عام للمسؤولين.

تفاصيل واجهة المواطن وعقد API ونماذج البيانات في [HOME_DASHBOARD.md](HOME_DASHBOARD.md)، وصفحة الجدول في [WATER_SCHEDULE.md](WATER_SCHEDULE.md)، والإعلانات في [COUNCIL_ANNOUNCEMENTS.md](COUNCIL_ANNOUNCEMENTS.md). لا تضيف هذه المرحلة جداول أو إعلانات تجريبية إلى قاعدة التطبيق.

تفاصيل البلاغات والحساب والنموذج والصلاحيات ومنع التكرار في [CITIZEN_REPORTS_ACCOUNT.md](CITIZEN_REPORTS_ACCOUNT.md). لا تُضاف بلاغات seed إلى قاعدة التطبيق؛ البلاغات تُنشأ فقط عند إرسال المواطن.

## التشغيل على Windows

المتطلبات: Node.js **22.12 أو أحدث**، وnpm، وحساب MongoDB Atlas لاستخدام التسجيل والدخول.

من مجلد المشروع في PowerShell:

```powershell
npm install
npm run setup:env
# أضف MONGODB_URI داخل server/.env كما هو موضح أدناه
npm run seed
npm run dev
```

افتح **http://127.0.0.1:5173** في Chrome. لتشغيل الواجهة وصفحة الزائر قبل تجهيز Atlas يكفي `npm run dev`؛ سيبدأ الخادم وتعيد خدمات المصادقة خطأ عربيًا واضحًا عند غياب قاعدة البيانات. لا يوجد تسجيل وهمي أو مخزن جلسات مؤقت كبديل لـ MongoDB.

`npm run setup:env` ينشئ `server/.env` مرة واحدة مع سر جلسات عشوائي. لا يستبدل إعداداتك إن كان الملف موجودًا. بعد تعديل إعدادات الخادم أعد تشغيله.

## ربط MongoDB Atlas

1. أنشئ cluster في Atlas، ومستخدم قاعدة بيانات بصلاحية `readWrite` لقاعدة التطبيق.
2. أضف عنوان IP العام لجهاز التطوير في **Network Access**. عند النشر أضف عنوان خروج خادم التطبيق.
3. من **Connect → Drivers** انسخ عنوان الاتصال. ضع القيمة محليًا في **`server/.env`**:

```dotenv
MONGODB_URI=mongodb+srv://YOUR_DB_USER:YOUR_URL_ENCODED_PASSWORD@YOUR_CLUSTER.mongodb.net/dor_el_may?retryWrites=true&w=majority
```

استبدل الرموز بقيمك الحقيقية، واستخدم URL encoding إذا احتوت كلمة مرور قاعدة البيانات على أحرف خاصة. لا ترسل بيانات الاتصال في المحادثات ولا تضفها إلى Git. جميع ملفات `.env` مستثناة، بينما ملفات `.env.example` قابلة للتتبع.

4. شغّل `npm run seed` اختياريًا لإضافة خمس حارات تجريبية دون حذف الحارات الحالية أو تغيير حالتها. **هذه أمثلة، وليست خريطة توزيع رسمية**. يمكنك إدخال أسماء معتمدة مباشرة في collection `zones` بدل تشغيل seed. لا تظهر في الواجهة حارات ثابتة مخزّنة في الكود.
5. شغّل `npm run dev`. عند نجاح الاتصال يظهر في الخادم `MongoDB connected`. حالة الاتصال متاحة أيضًا في `/api/health`.

راجع [دليل اتصال Atlas الرسمي](https://www.mongodb.com/docs/atlas/connect-to-cluster/) لإعداد المستخدم والشبكة والاتصال.

لفحص الاتصال دون إدخال بيانات، شغّل `npm run db:check`. يستخدم هذا الأمر و`npm run seed` ملف `server/.env` من مسار ثابت مستقل عن مجلد التشغيل، ولا يحتاجان إلى `SESSION_SECRET`. تبقى متغيرات بيئة العملية مقدّمة على ملف `.env`؛ تظهر ملاحظة إذا كان متغير `MONGODB_URI` في الطرفية يستبدل قيمة الملف.

يعرض seed مرحلة الفشل وتصنيفًا آمنًا للخطأ (صيغة URI، DNS، الاتصال، المصادقة، الصلاحيات أو الفهارس)، دون طباعة URI أو كلمة المرور أو الخطأ الخام. عند نجاحه يعرض عدد السجلات الجديدة والموجودة ويتحقق من وجود الحارات الخمس. يمكن تشغيله مجددًا دون إنشاء حارات مكررة أو إعادة تنشيط الحارات المعطّلة. لا تُعدّل كلمة المرور أو ترمّزها تلقائيًا؛ طبّق الترميز على جزء كلمة المرور مرة واحدة عند الحاجة. راجع [استكشاف أخطاء Atlas](https://www.mongodb.com/docs/atlas/troubleshoot-connection/) لمعاني أخطاء الشبكة والمصادقة.

## التجربة من هاتف Android على شبكة Wi-Fi نفسها

1. نفّذ `ipconfig` لمعرفة IPv4 الخاص ببطاقة Wi-Fi، مثل `192.168.1.6`.
2. أضف عنوان المتصفح على الهاتف إلى `APP_ORIGINS` في `server/.env`:

```dotenv
APP_ORIGINS=http://localhost:5173,http://127.0.0.1:5173,http://192.168.1.6:5173
```

3. شغّل من مجلد المشروع:

```powershell
npm run dev -- --host 0.0.0.0
```

4. إذا طلب Windows Firewall الإذن، اسمح لـ Node.js على **الشبكة الخاصة** المقصودة فقط. افتح `http://192.168.1.6:5173` في Chrome على الهاتف.

خادم Express يبقى على `127.0.0.1:3001`؛ يتصل الهاتف بـ Vite على المنفذ 5173، ويمر `/api` عبر proxy إلى Express. كل الطلبات تستخدم عناوين نسبية وcookies من المصدر نفسه. لا تكتب `localhost` على الهاتف لأنه يشير إلى الهاتف نفسه.

في التطوير عبر HTTP تكون `Secure=false` مع `HttpOnly` و`SameSite=Lax`. انتقل إلى HTTPS قبل النشر. تستخدم كل زيارة من عنوان مختلف (localhost أو IP) cookie مستقلة. انقطاع الاتصال أو تغيير عنوان IP قد يستلزم تحديث `APP_ORIGINS`. عدم وجود الحارات أو فشل تحميلها يمنع إنشاء الحساب حتى تصحيح الإعداد.

إذا ظهرت رسالة «تعذّر التحقق من مصدر الطلب»، طابق عنوان المتصفح كاملًا (البروتوكول وIP والمنفذ، دون مسار أو `/` في النهاية) مع `APP_ORIGINS` في `server/.env`. أُضيف العنوان `http://192.168.1.6:5173` إلى قائمة التطوير الحالية. عند تغيّر IP عدّل هذا الإدخال، ثم أوقف عمليتَي التطوير بـ `Ctrl+C` وأعد تشغيل الأمر أعلاه؛ تعديل `.env` وحده لا يعيد تحميل القائمة في خادم Express الجاري. إذا كنت تضبط `APP_ORIGINS` كمتغير في الطرفية فهو يتقدم على قيمة الملف، ويجب تحديثه أيضًا.

يحافظ Vite على `Origin` وcookies وترويسة `X-CSRF-Token` عند تمرير `/api`، ويتحقق Express من الأصل المحدد والرمز معًا. لا تستخدم `*` أو إعادة كتابة Origin أو تعطيل CSRF لحل المشكلة. تبقى قائمة الإنتاج منفصلة في بيئتها وتقبل HTTPS فقط؛ لا تضف عنوان التطوير HTTP إليها. بعد إعادة التشغيل جرّب الدخول من الهاتف، ثم أعد تحميل الصفحة للتأكد من بقاء الجلسة، ثم سجّل الخروج.

## الأوامر

| الأمر | الوظيفة |
|---|---|
| `npm run dev` | تشغيل Vite وExpress على الجهاز فقط |
| `npm run dev -- --host 0.0.0.0` | إتاحة Vite للشبكة المحلية لاختبار الهاتف |
| `npm run setup:env` | إنشاء ملف البيئة بسر عشوائي إن لم يكن موجودًا |
| `npm run seed` | إضافة حارات أولية اختيارية إلى قاعدة البيانات المضبوطة |
| `npm run db:check` | فحص إعداد قاعدة البيانات والاتصال وping دون إدخال بيانات |
| `npm run admin:create` | إنشاء مسؤول مجلس محليًا بإدخال كلمة مرور مخفي، دون تعديل حسابات موجودة |
| `npm run build` | إنتاج ملفات الواجهة داخل `client/dist` |
| `npm start` | تشغيل Express وخدمة الواجهة المبنية من المصدر نفسه |
| `npm test` | اختبارات التحقق، Argon2id، وسلوك الخادم دون قاعدة بيانات |
| `npm run test:db` | اختبارات تكامل على MongoDB حقيقي محلي مؤقت ومعزول |
| `npm run test:production` | بناء الواجهة وفحص خادم الإنتاج محليًا مع قاعدة مؤقتة، proxy، وإعادة التشغيل واستعادة الاتصال |
| `npm run test:ui` | اختبارات Chrome آلية على قاعدة محلية مؤقتة، وصور للشاشات |

اختبارات `test:db` و`test:ui` لا تقرأ `MONGODB_URI` الحقيقي ولا تكتب إلى Atlas. يحتاج أول تشغيل لتنزيل binary رسمي لـ MongoDB (كبير على Windows)، ويحفظه في `.cache/mongodb` المستثنى من Git. إذا كانت الشبكة مقيدة يمكن تشغيل `npm install` بعد ضبط `$env:MONGOMS_DISABLE_POSTINSTALL='1'` وتأجيل التنزيل إلى خطوة الاختبار. لا يحتاج تشغيل التطبيق العادي إلى MongoDB محلي.

## API والجلسات

| المسار | السلوك |
|---|---|
| `GET /api/auth/me` | المستخدم الحالي أو `null`، ورمز CSRF للجلسة |
| `POST /api/auth/register` | التحقق من البيانات، إنشاء resident، إنشاء جلسة، إرجاع المستخدم |
| `POST /api/auth/login` | التحقق من رقم الهاتف وكلمة المرور وإنشاء جلسة جديدة |
| `POST /api/auth/logout` | إتلاف الجلسة وحذف cookie |
| `POST /api/admin/login` | دخول مسؤول نشط فقط، مع CSRF وحدود مستقلة وتوليد جلسة جديدة |
| `GET /api/admin/me` | الملف الآمن للمسؤول الحالي؛ محمي بالدور على الخادم |
| `GET /api/admin/dashboard` | إحصاءات المجلس ومعاينة الأدوار والبلاغات من قاعدة MongoDB نفسها؛ محمي بالدور |
| `POST /api/admin/logout` | إتلاف جلسة المسؤول وحذف cookie؛ يتطلب جلسة مسؤول وCSRF |
| `GET /api/admin/water` | الأدوار النشطة، الأدوار المنشورة المتاحة للضخ، والسجل؛ مسؤول فقط |
| `GET/POST /api/admin/water-rounds` | قراءة جدول الإدارة أو إنشاء مسودة بطلب يمنع التكرار؛ مسؤول فقط |
| `PATCH /api/admin/water-rounds/:id` | تعديل دور مؤهل مع رقم المراجعة؛ مسؤول وCSRF |
| `POST /api/admin/water-rounds/:id/publish,start,end,cancel` | مسارات منفصلة للنشر وبدء الضخ وإنهائه والإلغاء مع منع التغييرات المتعارضة؛ مسؤول وCSRF |
| `GET /api/zones` | الحارات النشطة من MongoDB |
| `GET /api/home/summary` | ملخص المواطن المحمي: الضخ المعلن، دور حارته، ثلاثة أدوار قادمة وآخر إعلان منشور |
| `GET /api/water-rounds` | الجدول المنشور للمواطن المسجّل: الشهر والحارة والحالة، مع دفعات من 50 سجلًا |
| `GET /api/announcements` | إعلانات المجلس المنشورة للمواطن المسجّل، مع دفعات من 10 سجلات وفلتر آخر 30 يومًا |
| `GET /api/announcements/:id` | النص الكامل لإعلان منشور واحد؛ المسودات وغير المتاح تعيد 404 |
| `POST /api/reports` | إرسال بلاغ من resident مرتبط بالمستخدم وحارته من الجلسة؛ يتطلب CSRF ومعرّف إرسال لإعادة المحاولة الآمنة |
| `GET /api/reports/mine` | بلاغات صاحب الجلسة فقط، بالأحدث أولًا، على دفعات من 10؛ لا توجد قائمة عامة |
| `GET /api/health` | جاهزية الخادم وحالة قاعدة البيانات دون أسرار |

استجابة النجاح: `{ success: true, data: ... }`. الخطأ: `{ success: false, error: { code, message, fields? } }`. يتطلب POST نوع `application/json` وترويسة `X-CSRF-Token` المطابقة لما تعيده `/me`، مع التحقق من مصدر الطلب. يعالج العميل تحديث رمز CSRF تلقائيًا إذا انتهت الجلسة.

كلمات المرور مجزّأة بـ Argon2id (ذاكرة 19 MiB، مروران، توازٍ 1)، ولا تُعاد التجزئة في API. رقم الهاتف له فهرس فريد. يدعم التحقق أرقام الجوال المحلية الصحيحة للخطط الفلسطينية والإسرائيلية وفق metadata في `libphonenumber-js/max`، مع تحويل الأرقام العربية والفارسية إلى أرقام لاتينية. يُخزن رقم محلي موحّد يبدأ بـ05. لا تعني صحة صيغة الرقم أن ملكيته تحققت: **`phoneVerified=false` دائمًا عند التسجيل؛ لا يوجد SMS أو OTP**.

واجهة المرحلة الأولى تقبل الصيغة المحلية فقط. تدعم دالة `normalizePhone` خيارًا مستقلًا لصيغ `+970` و`+972` لتوسعة الواجهة لاحقًا مع بقاء مفتاح منع التكرار موحّدًا. بيانات المكتبة تتضمن بعض الأرقام الفلسطينية التي يمكن تمثيلها تحت كلا الرمزين. تُحدّث قواعد الترقيم مع تحديث المكتبة.

الجلسات محفوظة في collection `sessions` عبر `connect-mongo` لمدة 30 يومًا، وتُمدد مع الاستخدام. يُعاد توليد معرّف الجلسة بعد الدخول والتسجيل لمنع session fixation. لا تُخزّن كلمات مرور أو رموز جلسات في localStorage أو sessionStorage. يفحص العميل `/me` قبل إظهار المسارات، مع شاشة انتظار لتجنب وميض التحويل بين الصفحات.

حدود الدخول تُخزّن في `auth_rate_limits` بعمليات MongoDB ذرية وفهرس TTL، فتستمر بعد إعادة تشغيل الخادم وتُشارك بين النسخ: 25 محاولة لكل IP و10 لكل رقم خلال نافذة 15 دقيقة، و10 طلبات تسجيل لكل IP في الساعة، وحد عام 300 طلب API لكل IP خلال 15 دقيقة. تُجزّأ مفاتيح أرقام الهاتف في عدادات المحاولات. يُطبق الحد كذلك على محاولات الدخول الناجحة ضمن النافذة. تستخدم هذه الحدود نوافذ ثابتة.

مراجع التنفيذ: [جلسات Express](https://expressjs.com/en/resources/middleware/session/)، [connect-mongo](https://github.com/jdesboeufs/connect-mongo)، [OWASP لتخزين كلمات المرور](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)، [libphonenumber-js](https://github.com/catamphetamine/libphonenumber-js).

## تجهيز النشر على Render — بيئة اختبار منفصلة

أُعدّ المشروع لخدمة Render Web Service واحدة تخدم الواجهة المبنية وExpress API من أصل HTTPS واحد. لم يُنشأ مستودع GitHub أو خدمة Render ولم يُنفّذ نشر. الدليل الكامل في [RENDER_DEPLOY.md](RENDER_DEPLOY.md)، ويتضمن تدقيق الأسرار، قاعدة staging مستقلة، إعداد الأصل وproxy وAtlas، والتحقق واستكشاف الأخطاء.

أمر البناء: `npm ci --include=dev && npm run build`. أمر التشغيل: `npm start`. مجلد الخدمة هو جذر مستودع المشروع. في الإنتاج يستمع Express افتراضيًا على `0.0.0.0` والمنفذ `PORT` الذي توفره الاستضافة. مسار الصحة `/api/health` يعيد 503 عند تعذّر جاهزية قاعدة البيانات في الإنتاج.

ملفات `.env.example` تحتوي أسماء المتغيرات فقط دون قيم. تُضبط قيم الإنتاج في إعدادات الاستضافة، وتُترك أسرار `server/.env` المحلية دون تغيير. استخدم بيانات اعتماد وقاعدة Atlas منفصلتين للاختبار، دون نسخ حسابات المواطنين أو تشغيل seed أثناء النشر. أبقِ `SESSION_SECRET` ثابتًا في البيئة نفسها عبر إعادة التشغيل للحفاظ على الجلسات. تبقى cookie الإنتاج `__Host-door.sid` مع `Secure` و`HttpOnly` و`SameSite=Lax`، وتبقى حماية Origin وCSRF مفعلة.

أصبح للمشروع مستودع Git مستقل مرتبط بـ [Dor_El_May](https://github.com/jawadshahen28/Dor_El_May). قبل أي رفع لاحق، تحقّق أن جذر المستودع هو مجلد المشروع نفسه، مع بقاء ملفات البيئة والبيانات الخاصة مستثناة. أُضيف دعم PWA للتثبيت والتحديثات والفراغ الآمن دون اتصال؛ التفاصيل في [PWA.md](PWA.md).

## الصور والتصميم

نُسخت الصورتان الأصليتان إلى `client/public/images/talfit-village.jpg` و`talfit-council-logo.jpg`. احتُفظ بالشعار كاملًا؛ الصورة المتاحة لا تحتوي على أيقونة Facebook ظاهرة. لم تُستخدم صورة قرية مولّدة أو بديلة. يغيّر `object-fit` مساحة العرض حسب الشاشة، والملف الأصلي محفوظ دون تعديل. يوجد إسناد للمصور في خلفية التسجيل. رمز القطرة والرسم السفلي أصول SVG بسيطة أُنشئت بالكود للتوافق مع المرجع. الخط Tajawal محلي عبر npm دون طلب Google Fonts.

على الهاتف: صورة في الأعلى، هوية التطبيق، بطاقة بيضاء مستديرة، حقول بأيقونات، وأزرار زرقاء. على الشاشات الواسعة: صورة وهوية التطبيق بجانب النموذج. أُخذت درجات اللون والتباعد من الصورة المرجعية مع الحفاظ على قابلية القراءة وإمكانية الوصول.

نتائج التشغيل والاختبارات وحدود ما تم التحقق منه موثقة في [VERIFICATION.md](VERIFICATION.md). لقطات الواجهة المحلية في `artifacts/screenshots/`.
